How to Identify the Question Type

Read the keywords in the question and instantly know what type of problem it is and what formula to apply.

Keywords in Question Type What You Must Do
"TCO", "3-year", "should they migrate?", "on-premise vs cloud" TYPE A Calculate total 3-year cost for both, compare, recommend
"Total revenue", "price × usage", "how much earned" TYPE B Revenue = Price × Usage. Sum all services.
"On-demand", "reserved", "how many hours", "VM cost" TYPE C Identify on-demand or reserved, multiply rate × time
"Inbound", "outbound", "WAN", "GB of traffic", "network cost" TYPE D Match traffic type to rate, multiply GB × $/GB
"Which architecture?", "what should they implement?" TYPE E Apply decision rules: failure → clustering. Spike → bursting.
"IaaS vs PaaS vs SaaS", "which pricing model?" TYPE F Match service type to model using table
"Break-even", "when does cloud become cheaper?" TYPE G Set Cloud TCO = On-Premise TCO, solve for months
"On-demand or reserved?", "which is cheaper?" TYPE Cvar Calculate both, compare, pick lower cost
✎

TYPE A

TCO Analysis — Cloud vs On-Premise Decision

What is TCO?

Total Cost of Ownership (TCO) is the complete 3-year cost of an IT solution.

  • Calculate it for BOTH on-premise and cloud
  • Compare the two totals
  • The lower TCO wins — that's your recommendation
✎
Roman Urdu: TCO matlab 3 saal ki puri cost — hardware, software, labor, monthly charges sab mila ke. Dono ke liye calculate karo (on-premise aur cloud), phir compare karo. Jo sasta ho, woh choose karo.
The Master TCO Formula
TCO = Up-Front Cost + (Monthly On-Going Cost × Number of Months)
3-Year TCO (most common)
3-Year TCO = Up-Front Cost + (Monthly On-Going Cost × 36)

What Goes Into Each Cost Category?

Cost Category On-Premise Includes Cloud Includes
Up-Front (one-time) Hardware purchase × number of servers Labor for setup/integration only (NO hardware)
Up-Front (one-time) Software/licensing (full purchase) No software purchase (leased)
Up-Front (one-time) Labor for deployment Integration testing labor (can be HIGH if porting old app)
Monthly Environmental fees (power, cooling) Server instance usage fees ($/hr × hours × VMs)
Monthly Licensing fees Database storage fees ($/GB × GB)
Monthly Hardware maintenance Network/WAN outbound fees ($/GB × GB)
Monthly Labor/administration Labor/cloud resource administration
✎
Roman Urdu: On-premise mein upfront zyada hota hai — hardware kharidna, software kharidna, labor. Cloud mein upfront kam hota hai — sirf labor (setup/integration). Monthly costs mein cloud ka zyada ho sakta hai — per-hour VM charges, storage, network. Long-term mein compare karo.
Worked Example A1 Product Catalog Browser — ATN Case Study

Problem Statement

ATN wants to migrate its Product Catalog Browser to PaaS cloud. It runs on 4 virtual servers on 2 physical servers with a 300 GB database. Evaluate using a 3-year TCO analysis.

Given Data

On-Premise
  • Physical server: $7,500 each (×2)
  • Software for 4 VMs: $30,500
  • Deployment labor: $5,500
  • Monthly — Env: $750, Licensing: $520, HW Maintenance: $100, Labor: $2,600
Cloud
  • Upfront: $5,000 labor only
  • Server: 2.3 VMs × ($1.25 × 720)
  • DB: 300 GB × $1.09
  • Network: 420 GB × $0.10
  • Labor: $800/month

Step-by-Step Solution

Step 1
Calculate ON-PREMISE UP-FRONT Cost
  • Hardware: $7,500 × 2 physical servers = $15,000
  • Software: $30,500
  • Labor: $5,500
Total On-Premise Up-Front = $15,000 + $30,500 + $5,500 = $51,000
Step 2
Calculate ON-PREMISE MONTHLY Cost
  • Environmental Fees: $750
  • Licensing Fees: $520
  • Hardware Maintenance: $100
  • Labor: $2,600
Total Monthly On-Premise = $750 + $520 + $100 + $2,600 = $3,970/month
Step 3
Calculate CLOUD UP-FRONT Cost
  • No hardware, no software purchase
  • Labor only: $5,000
Total Cloud Up-Front = $5,000
Step 4
Calculate CLOUD MONTHLY Cost
  • Server Instance: 2.3 VMs × ($1.25/hr × 720 hrs) = 2.3 × $900 = $2,070
  • Database/Storage: 300 GB × $1.09/GB = $327
  • Network/WAN: 420 GB × $0.10/GB = $42
  • Labor: $800
Total Monthly Cloud = $2,070 + $327 + $42 + $800 = $3,239/month
Step 5
Calculate 3-YEAR TCO for Both
On-Premise TCO = $51,000 + ($3,970 × 36) = $51,000 + $142,920 = $193,920
Cloud TCO = $5,000 + ($3,239 × 36) = $5,000 + $116,604 = $121,604
Step 6
Compare and DECIDE
Cloud TCO ($121,604) < On-Premise TCO ($193,920) → MIGRATE TO CLOUD
Savings = $72,316 over 3 years.
✎
Roman Urdu: Step 1: On-premise ka upfront nikalo (hardware + software + labor). Step 2: On-premise ka monthly nikalo (sab monthly costs jodo). Step 3: Cloud upfront nikalo (usually sirf labor). Step 4: Cloud monthly nikalo (VM + DB + network + labor). Step 5: Dono ka TCO = Upfront + (Monthly × 36). Step 6: Jo kam hai woh choose karo.
★
Exam Tip: The 720 in "hours per month" = 24 hours/day × 30 days. Always use 720 unless told otherwise.
Worked Example A2 Client Database — Cloud NOT Recommended

Problem Statement

ATN's Client Database: 8 virtual servers, 2 physical servers, 1.5 TB database. Old code needs heavy porting.

Given Data

On-Premise
  • Physical server: $7,500 each (×2)
  • Software for 8 VMs: $15,200
  • Labor: $5,500
  • Monthly — Env: $1,050, Licensing: $300, HW Maint: $100, Admin: $4,500
Cloud
  • Upfront: $45,000 (high integration/porting labor)
  • Server: 3.8 VMs × $1.25 × 720
  • DB: 1,500 GB × $1.09
  • Network: 800 GB × $0.10
  • Labor: $1,200/month

Step-by-Step Solution

Step 1
ON-PREMISE UP-FRONT
  • Hardware: $7,500 × 2 = $15,000
  • Software: $15,200
  • Labor: $5,500
Total = $15,000 + $15,200 + $5,500 = $35,700
Step 2
ON-PREMISE MONTHLY
$1,050 + $300 + $100 + $4,500 = $5,950/month
Step 3
CLOUD UP-FRONT

Labor only (heavy integration/porting): $45,000

Warning: High because application code is old and hard to port!
Step 4
CLOUD MONTHLY
  • Server: 3.8 × ($1.25 × 720) = 3.8 × $900 = $3,420
  • DB: 1,500 GB × $1.09 = $1,635
  • Network: 800 GB × $0.10 = $80
  • Labor: $1,200
Total = $3,420 + $1,635 + $80 + $1,200 = $6,335/month
Step 5
3-YEAR TCO
On-Premise TCO = $35,700 + ($5,950 × 36) = $35,700 + $214,200 = $249,900
Cloud TCO = $45,000 + ($6,335 × 36) = $45,000 + $228,060 = $273,060

Note: Slides show $251,700 — slight rounding difference. Use your calculated value.

On-Premise TCO ($249,900) < Cloud TCO ($273,060) → DO NOT MIGRATE
Staying on-premise saves ~$23,160 over 3 years.
!
Why Cloud Lost:
  • Old application code requires very expensive porting ($45,000 upfront)
  • Large 1.5 TB database makes cloud storage costs high monthly ($1,635/mo)
✎
Roman Urdu: Yahan cloud mehenga kyun pada? Do wajuhaat: (1) Purani application ka code cloud ke liye convert karne mein $45,000 labor lagi — yeh upfront bahut zyada hai. (2) 1.5 TB database ka monthly charge $1,635 hai — on-premise se zyada. Is liye on-premise better nikla.
★
KEY LESSON: Cloud is not always cheaper! High integration/porting costs + large database = cloud may lose. Always calculate both!

Question 2 TYPE A

An organization has a very old legacy app. Cloud porting labor = $80,000. On-premise upfront = $30,000. On-premise monthly = $4,000. Cloud monthly = $3,500. Time frame = 3 years. Should they migrate?

Show Solution
On-Premise TCO = $30,000 + ($4,000 × 36) = $30,000 + $144,000 = $174,000
Cloud TCO = $80,000 + ($3,500 × 36) = $80,000 + $126,000 = $206,000
On-Premise ($174,000) < Cloud ($206,000) → DO NOT MIGRATE
Old app porting cost kills cloud advantage.
★

Quick Revision Summary — TYPE A

  • TCO = Up-Front + (Monthly × 36) for 3 years
  • Calculate for both on-premise and cloud
  • On-premise upfront: hardware + software + labor
  • Cloud upfront: usually labor only (but can be high for legacy apps)
  • Cloud monthly: VMs × rate × 720 + DB + network + labor
  • Lower TCO wins
Most Common Exam Trap: Forgetting to multiply monthly by 36 (not 3, not 12). Three years = 36 months. Also: cloud is NOT always cheaper — always calculate both.
2-Line Memory Trick: "Up-front plus monthly times thirty-six, compare the two and make your picks." On-premise: hardware+software+labor up front. Cloud: labor-only up front.

Revenue & Cost Calculations

The Core Formulas

Basic Revenue
Revenue = Price × Usage
Total Revenue (multiple services)
Total Revenue = Σ (Pricei × Usagei)   for all services
✎
Roman Urdu: Revenue ka simple formula hai: Price × Usage. Agar kai services hain toh har ek ke liye alag calculate karo phir sab jodo. Hourly aur daily alag alag calculate ho sakte hain.
Worked Example B1 Basic Revenue

Problem

A cloud company offers 3 services: Storage $10/month (5 units), Database $20/month (3 units), Computing $30/month (2 units). Find total revenue.

Step 1
Revenue = Price × Usage for each
  • Storage: $10 × 5 = $50
  • Database: $20 × 3 = $60
  • Computing: $30 × 2 = $60
Step 2
Sum all services
$50 + $60 + $60 = $170
Total Revenue = $170
Worked Example B2 Hourly & Daily Revenue

Problem

Service rates: Storage=$10, Database=$20, Computing=$30. Hourly usage: Storage=2, Database=1, Computing=3. Daily usage: Storage=3, Database=4, Computing=2. Find hourly and daily earnings.

Step 1
HOURLY Revenue
  • Storage: $10 × 2 = $20
  • Database: $20 × 1 = $20
  • Computing: $30 × 3 = $90
Total Hourly = $20 + $20 + $90 = $130/hour
Step 2
DAILY Revenue
  • Storage: $10 × 3 = $30
  • Database: $20 × 4 = $80
  • Computing: $30 × 2 = $60
Total Daily = $30 + $80 + $60 = $170/day
✎
Roman Urdu: Hourly aur daily alag hain: hourly ke liye hourly usage use karo, daily ke liye daily usage. Formula same hai — Price × Usage — sirf usage column badal jaata hai.

TYPE C

VM Instance Pricing Calculations

The Two VM Pricing Models

Feature On-Demand Reserved
Payment Per hour of actual use Upfront fee + discounted hourly rate
Commitment None — start/stop anytime 1–3 year commitment
Rate (example) S: $0.10/hr   M: $0.20/hr   L: $0.90/hr S: $55.10   M: $99.90   L: $249.90 (upfront)
When to Use Short-term, variable, unpredictable Long-term, stable, predictable
Calculation Hours Used × Hourly Rate Upfront + (Discounted Rate × Hours)
On-Demand Cost
Cost = VMs × Hourly Rate × Hours Used
Monthly On-Demand
Monthly = VMs × (Rate × 720)
Reserved Cost
Cost = Upfront Fee + (Discounted Rate × Hours)
✎
Roman Urdu: On-demand: VM chalao aur per-hour paisa do — flexible lekin mehenga. Reserved: pehle ek baar bada payment karo (upfront), phir har ghante ka rate kam hoga — long-term ke liye sasta.
Worked Example C1 Server Instance Cost — ATN Style

Problem

4 virtual servers, rate = $1.25/hour per VM. Due to auto-scaling, actual usage = equivalent to 2.3 VMs. Calculate monthly cost.

Step 1
Hours in a month = 24 × 30 = 720 hours
Step 2
Cost per VM per month = $1.25 × 720 = $900
Step 3
With scaling, actual usage = 2.3 VMs (not 4!)
Step 4
Monthly cost = 2.3 × $900
Monthly Server Cost = $2,070
✎
Roman Urdu: 4 VMs hain lekin auto-scaling ki wajah se sirf 2.3 VMs ke barabar use hota hai. Rate $1.25/hr. Month mein 720 hours. 2.3 × 1.25 × 720 = $2,070.
Worked Example C2 On-Demand vs Reserved Comparison

Problem

A company needs 2 medium VMs for 12 months. On-Demand rate: $0.20/hr. Reserved: $99.90 upfront per VM + $0.10/hr (discounted). Which is cheaper?

Step 1
ON-DEMAND for 12 months

Hours = 720 × 12 = 8,640 hours

On-Demand = 2 × $0.20 × 8,640 = $3,456
Step 2
RESERVED for 12 months

Upfront = 2 × $99.90 = $199.80

Usage = 2 × $0.10 × 8,640 = $1,728

Reserved = $199.80 + $1,728 = $1,927.80
Reserved ($1,927.80) < On-Demand ($3,456) → Use Reserved. Savings = $1,528.20
Worked Example C3 DTGOV Pricing with Surcharges

Problem

DTGOV charges: Small VM on-demand = $0.10/hr. Surcharge for CLUSTERED = 100% (double). Surcharge for RESILIENT = 120% (2.2×). A company runs 2 clustered small VMs for 500 hours. Calculate cost.

Step 1
Base cost = 2 VMs × $0.10/hr × 500 hrs = $100
Step 2
Clustered surcharge = 100% extra → multiply by (1 + 1.00) = 2.0
Step 3
Total = $100 × 2.0
Clustered Cost = $200
!
Don't Confuse: Clustered surcharge = 100% → multiply by 2.0. Resilient surcharge = 150% → multiply by 2.5. These are different!

TYPE D

Network & Storage Cost Calculations

All Network & Storage Formulas

Inbound Network
Cost = GB × $/GB    (usually $0 — free!)
Outbound Network
Cost = GB × $/GB    (e.g. $0.01/GB or $0.10/GB)
Intra-Cloud WAN
Cost = GB × $/GB    (between regions)

TYPE G

Break-Even Analysis

What is Break-Even?

Break-even is the point in time when the cumulative cost of Cloud equals the cumulative cost of On-Premise.

  • Before this point: one option is cheaper
  • After this point: the other takes over
Break-Even Month Formula
N = (OP Up-Front − Cloud Up-Front) ÷ (Cloud Monthly − OP Monthly)
!
Important: This formula only works when Cloud Monthly > On-Premise Monthly. If cloud monthly is LOWER, cloud is cheaper from day 1 after upfront comparison.
✎
Roman Urdu: Break-even matlab: kis mahine dono ki total cost equal ho jaati hai. Isse pehle ek sasta, baad mein doosra. Formula: (OP Upfront - Cloud Upfront) ÷ (Cloud Monthly - OP Monthly) = break-even month.
Worked Example G1No Break-Even Needed

Problem

On-Premise: $51,000 upfront, $3,970/month. Cloud: $5,000 upfront, $3,239/month. Find the break-even point.

Analysis
  • On-Premise upfront ($51,000) >> Cloud upfront ($5,000)
  • Cloud monthly ($3,239) < On-Premise monthly ($3,970)

Cloud is cheaper BOTH in upfront AND monthly!

Cloud is cheaper from Month 1 — no break-even needed. Use cloud immediately.

Scenario Question 1 Hybrid Network Firewall Architecture & Rules

Scenario: A medium-sized company has three departments: HR, Finance, and IT. The company wants to secure its network from unauthorized access while allowing employees to access the internet and internal resources safely.

Requirements:

  1. Only the Finance department should access the accounting server.
  2. Employees can browse the web but cannot access social media websites during office hours (08:00 - 18:00).
  3. External users should only access the company's public web server.
  4. The IT department should have full network access for maintenance.
  5. The network must be protected from malware and unauthorized login attempts.

Tasks:

  • (a) Design a firewall architecture for the company network and explain the rationale.
  • (b) Draw/reference a simple network diagram showing firewall placement and zones.
  • (c) Write at least four firewall rules based on the requirements.
Show Solution & Diagram
Solution & Diagram

(a) Design & Rationale

A Hybrid Firewall Architecture is recommended because the company needs to support both external users accessing public services and strict, stateful departmental access controls internally:

  • Outer Firewall (Packet-Filtering): Placed at the network perimeter. It filters traffic by IP and port, blocking initial untrusted packets and ensuring external traffic only reaches the DMZ.
  • DMZ (Demilitarized Zone): An isolated zone containing the Public Web Server (reachable from the internet on ports 80/443) and an Application Proxy Server (to inspect and filter content such as social media URLs).
  • Inner Firewall (Stateful Packet Inspection - SPI): Placed between the DMZ and the internal department LANs. It maintains a state table, permits bidirectional employee web traffic initiated from inside, strictly separates internal departments (HR, Finance, IT), and blocks all traffic to the Accounting Server except from the Finance IP subnet.
  • IDS/IPS (Intrusion Detection/Prevention): Integrated into the inner firewall or proxy to satisfy Requirement 5 (malware detection and threat prevention).

Scenario Question 3 Zero Trust Network Architecture (ZTN)

Scenario: A modern cloud-native software firm operates with fully remote engineers. They access high-value code repositories and customer databases. The CTO states: "We want to move away from IP-based perimeter firewalls completely. No user or device should be trusted by default."

Show Solution & Diagram
Solution & Diagram

(a) Paradigm, PDP, and PEP

The paradigm is Zero Trust Network Architecture (ZTN). In Zero Trust, perimeter security is discarded in favor of identity- and context-aware microsegmentation:

  • Policy Decision Point (PDP): Evaluates user credentials (IAM/MFA), device health posture, and context to emit a verdict.
  • Policy Enforcement Point (PEP): Data plane component that intercepts connections and allows or blocks access to specific resources based on PDP guidance.

(c) The 3 Core Principles vs Traditional Firewalls

  1. Never Trust, Always Verify: assess posture dynamically on every connection, not just at perimeter.
  2. Least Privilege Access: restrict access strictly based on user roles and identity.
  3. Assume Breach: isolate resources in secure micro-segments and encrypt all traffic.

Common Exam Mistakes to Avoid

× Forgetting to multiply by 36 months (not 3, not 12 — it's 36 for 3 years)
× Using "number of VMs installed" instead of "effective VMs after auto-scaling"
× Treating INBOUND traffic as chargeable (it's usually FREE — don't add it)
× Forgetting hardware cost in on-premise upfront (servers × price each)
× Including sunk costs in the TCO decision (they are irrelevant — ignore them)
× Adding up-front to monthly without multiplying monthly by time period
× Using $0.10/hr as monthly cost instead of $0.10 × 720 = $72/month
× Confusing "clustered" (×2) with "resilient" (×2.5)
× Recommending cloud when client has old legacy app with high porting cost
× Not showing working steps — always show every calculation!
